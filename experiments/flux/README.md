# INTRA on FLUX.1-dev (image generation)

Code for the image-generation experiments of *INTRA: Interleaved Non-contiguous Token Sparse
Attention* (Sections 4.7, 6.1, 6.2; Tables 1, 2, 6, 13). FLUX.1-dev is adapted to INTRA sparse
attention by LoRA self-distillation from the dense model, then sampled with the INTRA CUDA kernel.

| file | what it is |
|---|---|
| `intra_processor.py` | diffusers attention processor implementing the two image patterns, plus `set_intra_processors(transformer)` which installs them on all 57 FLUX attention layers. Training path: SDPA with a dense additive mask (has a backward). Inference path: the `intra_attn` CUDA kernel, used automatically under `torch.no_grad()` at 1024 x 1024 and 2048 x 2048 when the package is installed. |
| `train_distill.py` | LoRA self-distillation trainer (adapted from diffusers' `train_dreambooth_lora_flux.py`). Student = FLUX + LoRA + INTRA, teacher = frozen dense FLUX, loss = MSE between their flow predictions. |
| `scripts/train.sh` | launcher with the archived training configuration of the paper's FLUX run (table below). |
| `test_masks.py` | CPU check that the masks (from `intra_attn/reference.py`, which the kernel is tested against) equal the original training code's loop-built masks. |
| `requirements.txt` | Python dependencies (diffusers pinned to 0.33.1). |

## Attention patterns

The joint FLUX sequence is 512 T5 text tokens followed by a width x width grid of image tokens
(64 x 64 = 4096 at 1024 x 1024, 128 x 128 = 16384 at 2048 x 2048). Every query, text or image, always attends to all 512 text keys. On image keys:

- **Scatter** (8 groups): image token (r, c) belongs to group `(r % 2) * 4 + c % 4`, i.e. one token from
  every 2 x 4 neighbourhood; text query chunk j (tokens 64j to 64j+63) rides with group j.
- **Gather 0**: each 8 x 8 patch of image queries attends to the 16 x 16 window of image keys centred on
  it (shifted inwards at the borders). Text queries keep their Scatter rows.
- **Schedule**: the pattern switches every two layers over the 19 double-stream and then 38 single-stream
  blocks: Scatter, Scatter, Gather 0, Gather 0, ...

The masks come from `intra_attn/reference.py`, the specification the CUDA kernel is tested against
(`tests/test_kernel.py`, widths 64 and 128). `python test_masks.py` checks them element by element
against the loop-based mask builders of the original training code (0 mismatches at 1024 x 1024;
densities 22.2% and 17.3%).

## Setup

```bash
pip install -r requirements.txt
# INTRA CUDA kernel (needed only for fast inference), from the repository root:
pip install .
```

Training data and its loader come from [CLEAR](https://github.com/Huage001/CLEAR): the 10K
1024 x 1024 images generated by FLUX.1-dev
([data_000000.tar](https://huggingface.co/datasets/jackyhate/text-to-image-2M/resolve/main/data_1024_10K/data_000000.tar)).
Follow CLEAR's README to unpack it into a folder (`t2i_1024`) and to cache the T5/CLIP prompt
embeddings and VAE latents (`cache_prompt_embeds.sh`, `cache_latent_codes.sh`). `train_distill.py`
reads only the cached files, through CLEAR's `dataset.py`.

## Training

```bash
cd experiments/flux
CLEAR_DIR=/path/to/CLEAR DATA_DIR=/path/to/t2i_1024 bash scripts/train.sh
# optional: MODEL=<local FLUX.1-dev dir>  OUTPUT_DIR=...  REPORT_TO=tensorboard
```

| setting | value |
|---|---|
| base model | `black-forest-labs/FLUX.1-dev`, bf16, resolution 1024 |
| LoRA | rank 4, alpha 4, Gaussian init; double-stream blocks: attention (`to_q/k/v`, `to_out.0`, `add_q/k/v_proj`, `to_add_out`) and MLPs (`ff`, `ff_context`); single-stream blocks: `attn.to_q/k/v` |
| loss | `mean((student_pred - teacher_pred)^2)`, no flow-matching term |
| timesteps | uniform (`weighting_scheme=none`), guidance embedding 1.0 for teacher and student |
| optimizer | Prodigy, lr 1.0, betas (0.9, 0.999), weight decay 1e-4, constant schedule, no warmup, grad-norm clip 1.0 |
| batch | 1 per GPU x 8 gradient-accumulation steps, gradient checkpointing, seed 42 |
| length | `--max_train_steps 50000` is an upper bound; the paper reports 43 A100 GPU-hours of fine-tuning |

Each epoch ends with a training-state checkpoint `OUTPUT_DIR/checkpoint-<step>/` (LoRA weights in
`pytorch_lora_weights.safetensors`) and validation images from the sparse student; the final LoRA is
written to `OUTPUT_DIR/pytorch_lora_weights.safetensors`. `--checkpointing_steps` only prunes old
checkpoints when `--checkpoints_total_limit` is set.

## Inference with the kernel

```python
import torch
from diffusers import FluxPipeline
from intra_processor import set_intra_processors

pipe = FluxPipeline.from_pretrained("black-forest-labs/FLUX.1-dev", torch_dtype=torch.bfloat16).to("cuda")
pipe.load_lora_weights("output/intra_flux")        # or output/intra_flux/checkpoint-<step>
set_intra_processors(pipe.transformer)             # after loading the LoRA
image = pipe("A photo of dog in a bucket", height=1024, width=1024).images[0]
```

The kernel path needs `intra_attn` built, CUDA bf16 tensors, 512 text tokens (the default
`max_sequence_length=512`) and a 1024 x 1024 or 2048 x 2048 image (`height=width=2048` for the
latter). Otherwise the processor falls back to masked SDPA with the same pattern, which works for any
square resolution whose latent side is a multiple of 8 but gives no speedup;
`set_intra_processors(pipe.transformer, use_kernel=False)` forces that path.

## Paper results and what reproduces them

| paper | how to reproduce |
|---|---|
| Table 2, 1024 x 1024 INTRA row (FID / LPIPS / CLIP-I, generation time) | train with `scripts/train.sh`; sample with the snippet above; score with CLEAR's protocol (see below) |
| Table 1 (single attention latency, 4K and 16K) | `python benchmarks/bench_kernel.py image` at the repository root |
| Table 6b (8 groups), Table 13b (2 layers) | the shipped configuration |
| Table 2, 2048 x 2048 INTRA row | the same LoRA (trained at 1024 x 1024), sampled at `height=width=2048` with the snippet above; FLUX.1-dev generates 2K natively, so no separate 2K training is needed |
| Table 6a (Scatter only, Gather 0 only), Table 6b (4 and 16 groups), Table 13b (1, 3, 4 layers) | not shipped as configurations; only the 8-group, switch-every-two-layers setting is included. The schedule lives in `set_intra_processors` |
| Table 13a (SD 1.5), CLEAR baselines | external models; for CLEAR use the [CLEAR repository](https://github.com/Huage001/CLEAR) |

**Evaluation protocol.** Following CLEAR ([Liu et al., 2025](https://arxiv.org/abs/2412.16112)), the
paper samples 5,000 COCO 2014 validation prompts and reports FID, LPIPS and CLIP-I of the generated
images.

## Notes

- The CUDA kernel is compiled for 1024 x 1024 and 2048 x 2048 images. Only 1024 x 1024 training is
  needed: the same LoRA is used for 2048 x 2048 generation.
- The kernel is forward-only; training uses masked SDPA with a dense bf16 mask (4608 x 4608, ~42 MB
  per pattern and device), so the student runs in bf16 (`--mixed_precision bf16`).
